1. STEP 1 (BASIC DETAILS) IMPLEMENTATION & SOURCE OF TRUTH
------------------------------------------------------------
A. Full Name:
- Prefill: public.profiles.full_name (fallback: auth.users metadata full_name).
- Validation: Required, trimmed, 2–120 characters.
- Editable by Producer.
- Persistence: Saved directly to public.profiles.full_name.

B. Email Address:
- Prefill: Authoritative from Supabase Auth user.email.
- Read-Only: Displayed clearly with 'Read Only' badge.
- Email editing is not supported in the onboarding flow.

C. Phone Number:
- Authenticated Phone: If Supabase Auth phone exists, it is displayed as read-only with 'Verified Auth' badge.
- Contact Phone: If no auth phone exists, public.profiles.phone is treated strictly as a contact phone number (not verified authentication).
- Validation: When editable, validates 10-digit Indian mobile format (starting with 6–9).
- Persistence: Saved to public.profiles.phone.

D. Step 1 Navigation & Persistence Behavior:
- Tapping Continue validates form inputs and persists Full Name and Contact Phone to public.profiles.
- Only after successful save does the wizard advance to Step 2.
- If persistence fails, the user remains on Step 1 with a friendly error message.
- Draft values survive forward and backward step navigation via ProducerOnboardingProvider.


2. STEP 2 (BUSINESS & CRAFT DETAILS) IMPLEMENTATION & BEHAVIOR
------------------------------------------------------------
A. Business / Workshop Name:
- Mapped to: public.producer_profiles.business_name.
- Prefill: producer_profiles.business_name.
- Validation: Required, trimmed, 2–120 characters.
- Helper text: "Name of your business, workshop, or home-based work".

B. Craft / Product Category:
- Mapped to: public.producer_profiles.craft_category.
- UI: Single primary category selection using visual ChoiceChips with icons.
- Standard Categories: Food & Homemade Products, Handicrafts, Handloom & Textiles, Clothing & Embroidery, Jewellery & Accessories, Woodwork, Metal Craft, Home Decor, Beauty / Personal Care, Other.
- 'Other' Option: Displays dedicated input for custom artisanal/product category (2–60 characters).
- Prefill: Known standard categories pre-select the corresponding chip; custom values select 'Other' and populate the custom category field.

C. Short Description:
- Mapped to: public.producer_profiles.bio.
- Prefill: producer_profiles.bio.
- Validation: Optional, trimmed, max 500 characters. Live character counter displayed.
- Helper text: "Tell buyers what you make in a few words".

D. Step 2 Navigation & Persistence Behavior:
- Tapping Continue validates business name, category, and bio length, then calls ProducerAuthService.updateBusinessProfile to update public.producer_profiles.
- Only after successful save does the wizard advance to Step 3 (Location Details).
- If persistence fails, user stays on Step 2 with entered values preserved and a friendly error message.
- All values survive forward (Step 3) and backward (Step 1) navigation.

4. SECURITY & TRUST BOUNDARIES
------------------------------------------------------------
- Client-Writable Fields: business_name, craft_category, bio, state, district, city, pincode, address, gst_registered, gstin, full_name, phone (contact).
- Trusted-Backend-Only Fields: onboarding_status, pan_last4, pan_hash, pan_verification_status, aadhaar_last4, aadhaar_verification_reference, aadhaar_verification_status, gst_verification_status, address_verification_status, verification_status.
- Direct Mutation Prohibited: Migration 005 explicitly revokes client INSERT/UPDATE privileges on onboarding_status.
- Prohibited from Storage: Raw 12-digit Aadhaar numbers and plaintext PAN numbers.


5. RUNTIME ISSUE RESOLUTION: UPDATED_AT COLUMN PRIVILEGE (42501)
------------------------------------------------------------
- Symptom: Real manual testing of Step 1 save failed with "Failed to save basic details".
- Root Cause: Flutter client payload manually included 'updated_at': DateTime.now().toIso8601String(). In Migration 001, 'updated_at' was intentionally excluded from client UPDATE privileges (GRANT UPDATE only covers user-editable columns). PostgreSQL returned code 42501 (permission denied for column updated_at).
- Fix Applied: Removed manual 'updated_at' from updateBasicProfile, updateBusinessProfile, and updateLocationProfile.
- Database Authority: Database triggers trg_profiles_updated_at and trg_producer_profiles_updated_at execute handle_updated_at() to manage timestamps automatically with SECURITY DEFINER. No SQL schema migration was required.
