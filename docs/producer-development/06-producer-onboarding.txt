1. STEP 1 (BASIC DETAILS) IMPLEMENTATION & SOURCE OF TRUTH
------------------------------------------------------------
A. Full Name:
- Prefill: public.profiles.full_name (fallback: auth.users metadata full_name).
- Validation: Required, trimmed, 2–120 characters.
- Editable by Producer.
- Persistence: Saved directly to public.profiles.full_name.

B. Email Address:
- Prefill: Authoritative from Supabase Auth user.email.
- Read-Only: Displayed clearly with 'Read Only' badge.
- Email editing is not supported in the onboarding flow.

C. Phone Number:
- Authenticated Phone: If Supabase Auth phone exists, it is displayed as read-only with 'Verified Auth' badge.
- Contact Phone: If no auth phone exists, public.profiles.phone is treated strictly as a contact phone number (not verified authentication).
- Validation: When editable, validates 10-digit Indian mobile format (starting with 6–9).
- Persistence: Saved to public.profiles.phone.

D. Step 1 Navigation & Persistence Behavior:
- Tapping Continue validates form inputs and persists Full Name and Contact Phone to public.profiles.
- Only after successful save does the wizard advance to Step 2.
- If persistence fails, the user remains on Step 1 with a friendly error message.
- Draft values survive forward and backward step navigation via ProducerOnboardingProvider.


2. SECURITY & TRUST BOUNDARIES
------------------------------------------------------------
- Client-Writable Fields: business_name, craft_category, bio, state, district, city, pincode, address, gst_registered, gstin, full_name, phone (contact).
- Trusted-Backend-Only Fields: onboarding_status, pan_last4, pan_hash, pan_verification_status, aadhaar_last4, aadhaar_verification_reference, aadhaar_verification_status, gst_verification_status, address_verification_status, verification_status.
- Direct Mutation Prohibited: Migration 005 explicitly revokes client INSERT/UPDATE privileges on onboarding_status.
- Prohibited from Storage: Raw 12-digit Aadhaar numbers and plaintext PAN numbers.
